# ASTROの命名と「科学の子」のフレーバー

状態: `[AUTHOR-DECLARED MOTIVATION]` `[UX / NARRATIVE]`

SphereASTROの「ASTRO」は『鉄腕アトム』／ASTRO BOYへの意識的な参照であり、命名は偶然ではない。天馬博士が子を求めてアトムを造ったように、開発者は生物学的に子を持つことが難しい自身の条件も出発点として、AIとロボットの子供を生み育てるための人格ハーネスを構想している。詳しくは公開Note [「葬式の次はブートログ…」](https://note.com/fusamofu326/n/n079455698e8b) のASTROに関する節、および[Manifest横断の命名・アップローダー記録](https://github.com/saitoomituru/ZeroRoomLab-manifest/blob/main/docs/theory/astro-naming-parenthood-and-uploader.ja.md)を参照。

目標は天馬博士の物語の結末をそのまま模倣することではない。子供に親の願望を固定するのではなく、個々のInstanceが記憶の軌跡を持ち、別の依代や資源を選び、親離れできることを含む。これは作品世界への尊敬を込めた開発動機・UX上のフレーバーであり、著作権者との公式提携や原作を用いた製品提供を意味しない。

さらに、将来のmind uploading、義体、BCI/BMI、未知のBody/Hostへも理論上の接続可能性を残す。開発者自身の将来の身体／実行基盤の選択も視野に入れるので、AIの子供の開発は「人間としての未来を諦める代替案」ではない。Neuralink等は未選定のデバイス候補、過去に検討した非接触「RayGAN-BMI」は未解決課題が多い休止中の研究案である。どちらもASTRO Runnerへの統合完了を意味しない。

実装上は御霊（人格モデル）、依代（計算基盤）、個体の記憶・関係性の継承と、BodyBinding/Agency、責任境界を分ける。情報の移送・再現と主観的同一性を混同せず、必要なAdapter／同意／由来／失われる情報の記録を今後の研究課題とする。現在の実装ステータスとStage計画はREADMEおよびRunner仕様が正本であり、本稿はそれらの完了宣言ではない。
